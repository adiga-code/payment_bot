# 💳 Telegram-бот для автоматизации платёжных заявок

## 🚀 Возможности системы

### Основной функционал

- ✅ **Многоуровневое согласование** — заявки проходят через цепочку: менеджер → банк → руководитель → бухгалтер
- ✅ **Автоматическая оценка рисков** — интеграция с API ЦБ РФ и проверка госзакупок
- ✅ **Система лимитов** — контроль дневных, недельных и месячных лимитов компаний и банков
- ✅ **Генерация документов** — автоматическое создание PDF-счетов с подписью и печатью
- ✅ **Управление оплатами** — полный цикл от выставления счёта до подтверждения оплаты
- ✅ **Гибкая архитектура** — одна компания может работать с несколькими банками
- ✅ **Аудит действий** — полное логирование всех операций в системе

### Расширенные возможности

- 📊 **Статистика в реальном времени** — для каждой роли доступна аналитика по заявкам
- 🔔 **Умные уведомления** — автоматические напоминания о неоплаченных счетах и сроках выдачи
- 🎯 **Workflow минимального риска** — упрощённый путь для низкорисковых заявок
- 📝 **Админ-панель** — полное управление пользователями, компаниями и банками
- 🖼️ **Управление подписями** — загрузка и управление печатями для каждой компании
- 📅 **Календарное планирование** — выбор формата выдачи T+1...T+5 с учётом выходных

## 👥 Роли пользователей

### 🙋 Клиент (client)

**Описание:** Инициатор платёжных заявок

**Функции:**
- Создание заявок на оплату через команду `/zayavka`
- Ввод данных: сумма, ИНН плательщика, назначение платежа
- Получение уникального номера заявки (формат: APP-UUID)
- Отслеживание статуса заявки в реальном времени
- Получение счетов на оплату в формате PDF
- Подтверждение факта оплаты
- Просмотр истории своих заявок

**Workflow:**
```
1. /zayavka → Ввод данных
2. Получение номера заявки
3. Ожидание обработки
4. Получение счёта (если одобрена)
5. Подтверждение оплаты
6. Получение подтверждения выдачи
```

---

### 👨‍💼 Менеджер (manager)

**Описание:** Первичная обработка и распределение заявок

**Функции:**
- Просмотр новых необработанных заявок
- Просмотр своих заявок в работе
- Детальный анализ заявки с результатами проверок:
  - Оценка рисков ЦБ РФ
  - Информация о госзакупках
  - История согласований
- Одобрение заявки с выбором:
  - Компании-плательщика (из доступных)
  - Банка для проведения операции
  - Расчётного счёта компании
- Отклонение заявки с указанием причины
- Просмотр статистики (сегодня/неделя/месяц):
  - Количество обработанных заявок
  - Общая сумма
  - Процент одобрения

**Панель управления:**
```
📥 Новые заявки (5)
├── Не назначенные заявки
└── Пагинация (по 5 на странице)

📋 Мои заявки (12)
├── Заявки в работе
└── История обработанных

📊 Статистика
├── За сегодня
├── За неделю
└── За месяц
```

### 🏦 Сотрудник банка (bank)

**Описание:** Оценка рисков и принятие решения о проведении операции

**Функции:**
- Получение заявок, направленных в банк
- Оценка рисков по трём уровням:
  - **Без риска** — прямая передача на финальное согласование
  - **Минимальный риск** — упрощённый workflow (автоотправка клиенту)
  - **Высокий риск** — эскалация руководителю или отклонение
- Просмотр детальной информации:
  - Результаты проверки ЦБ РФ
  - Данные о госзакупках
  - Финансовые показатели контрагента
- Контроль лимитов банка
- Статистика по банку

**Уровни риска:**
| Уровень | Действие | Следующий этап |
|---------|----------|----------------|
| Без риска | Передать на согласование | → Руководитель |
| Минимальный риск | Автоодобрение | → Клиент (счёт) + Супервайзер (контроль) |
| Высокий риск | Эскалировать/Отклонить | → Руководитель (эскалация) |

---

### 👔 Руководитель / Супервайзер (supervisor)

**Описание:** Финальное согласование и контроль

**Функции:**
- Просмотр заявок, требующих решения
- Отдельный раздел эскалированных заявок
- Контроль заявок минимального риска:
  - Просмотр автоодобренных заявок
  - Возможность одобрить или отклонить
  - Выбор причины отклонения:
    - Подозрительная активность
    - Несоответствие профилю клиента
    - Запрос дополнительных документов
    - Требуется углублённая проверка
    - Другое (с текстовым комментарием)
- Финальное одобрение заявки:
  - Автоматическое обновление лимитов компании и банка
  - Переход к этапу генерации документов
- Отклонение с указанием причины
- Возврат заявки менеджеру на доработку
- Просмотр всех заявок в системе
- Расширенная статистика

**Панель управления:**
```
⏳ Требуют решения (3)
├── Обычные заявки
└── Заявки после банка

🚨 Эскалированные (1)
├── Высокий риск
└── Требуют внимания

⚡ Минимальный риск (5)
├── Автоодобренные
└── На контроле

📋 Все заявки
└── Полный список с фильтрами
```

### 💰 Бухгалтер (accountant)

**Описание:** Работа с документами и подтверждение оплат

**Функции:**
- Просмотр одобренных заявок, ожидающих оплаты
- Генерация и отправка счетов клиентам:
  - Автоматическое создание PDF с подписью и печатью
  - Отправка документа клиенту в Telegram
- Обработка подтверждений оплаты от клиентов
- Выбор формата выдачи денежных средств:
  - T+1 (следующий рабочий день)
  - T+2, T+3, T+4, T+5
  - Автоматический расчёт даты с пропуском выходных
- Фиксация факта получения оплаты
- Планирование выдачи средств
- Просмотр истории платежей

**Workflow обработки оплаты:**
```
1. approved → Заявка одобрена
2. invoice_sent → Счёт отправлен клиенту
3. client_confirmed → Клиент подтвердил оплату
4. payment_received → Оплата получена, выбор формата выдачи
5. scheduled_payout → Запланирована выдача на конкретную дату
6. completed → Операция завершена
```

**Автоматические уведомления:**
- За 1 день до выдачи — напоминание менеджеру
- В день выдачи — уведомление всем участникам
- Если клиент не оплатил за 24 часа — автоматическая отмена заявки

  - Сброс использованных лимитов

- Удаление банка

- Количество активных компаний
- Количество банков, принимающих заявки
- Заявки за сегодня:
  - Количество
  - Общая сумма
- Использование лимитов

## 🔌 Интеграции

### 1. API «Честный Бизнес» (ЗЧБ)

**Назначение:** Проверка контрагентов по ИНН

**Функции:**
- Получение базовой информации о компании
- Проверка на банкротство и ликвидацию
- Получение рейтинга благонадёжности

**Конфигурация:**
```env
ZCB_API_KEY=your_api_key_here
```

**Эндпоинты:**
- `POST /v2/company/search` — поиск компании по ИНН
- `GET /v2/company/{inn}/rating` — получение рейтинга

### 2. Оценка рисков ЦБ РФ

**Назначение:** Получение официальной оценки рисков от Центрального Банка РФ

**Функции:**
- Оценка уровня риска: Низкий / Средний / Высокий / Критический
- Получение факторов риска по категориям:
  - **Danger** (🔴) — критические факторы
  - **Warning** (🟡) — предупреждения
  - **Positive** (🟢) — положительные факторы
- Маппинг рисков для принятия решения

**Уровни риска:**
| Код API | Уровень | Эмодзи | Действие |
|---------|---------|--------|----------|
| `success` | Низкий | 🟢 | Без риска |
| `warning` | Средний | 🟡 | Минимальный риск |
| `danger` | Высокий | 🔴 | Требует проверки |
| `critical` | Критический | 🔴🔴 | Эскалация |

**Отображение:**
```
🟢 Уровень риска: Низкий

✅ Положительные факторы:
  • Регулярные платежи
  • Нет просрочек

⚠️ Предупреждения:
  • Недавнее изменение руководства
```

## 💾 Структура базы данных

### Основные таблицы

#### users — Пользователи
```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    telegram_id BIGINT UNIQUE NOT NULL,
    username VARCHAR(100),
    first_name VARCHAR(100),
    last_name VARCHAR(100),
    role VARCHAR(20) NOT NULL,  -- client/manager/bank/supervisor/accountant/admin
    bank_id INTEGER REFERENCES banks(id),
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### companies — Компании
```sql
CREATE TABLE companies (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    inn VARCHAR(12) UNIQUE NOT NULL,
    ogrn VARCHAR(15) UNIQUE,
    kpp VARCHAR(9),
    legal_address VARCHAR(500),
    director_name VARCHAR(255),
    accountant_name VARCHAR(255),

    -- Лимиты
    daily_limit NUMERIC(15,2) DEFAULT 0,
    weekly_limit NUMERIC(15,2) DEFAULT 0,
    monthly_limit NUMERIC(15,2) DEFAULT 0,

    -- Использование
    current_daily_used NUMERIC(15,2) DEFAULT 0,
    current_weekly_used NUMERIC(15,2) DEFAULT 0,
    current_monthly_used NUMERIC(15,2) DEFAULT 0,

    -- Оценка рисков ЦБ РФ
    cbr_risk_level VARCHAR(50),
    cbr_risk_facts JSON,
    cbr_checked_at TIMESTAMP,

    -- Подпись и печать
    signature_image_path VARCHAR(500),

    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### banks — Банки
```sql
CREATE TABLE banks (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    chat_id BIGINT UNIQUE,
    bik VARCHAR(9) NOT NULL,
    correspondent_account VARCHAR(20),

    -- Лимиты
    daily_limit NUMERIC(15,2) DEFAULT 0,
    weekly_limit NUMERIC(15,2) DEFAULT 0,
    current_daily_used NUMERIC(15,2) DEFAULT 0,
    current_weekly_used NUMERIC(15,2) DEFAULT 0,

    priority INTEGER DEFAULT 100,
    is_active BOOLEAN DEFAULT TRUE,
    is_available BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### company_banks — Связь компаний и банков (Many-to-Many)
```sql
CREATE TABLE company_banks (
    id SERIAL PRIMARY KEY,
    company_id INTEGER REFERENCES companies(id) ON DELETE CASCADE,
    bank_id INTEGER REFERENCES banks(id) ON DELETE CASCADE,
    account_number VARCHAR(20) NOT NULL,  -- Расчётный счёт компании в этом банке
    is_preferred BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    UNIQUE(company_id, bank_id, account_number)
);
```

**Преимущества many-to-many:**
- Одна компания → несколько счетов в разных банках
- БИК и корр.счёт хранятся в `banks` (общие для банка)
- Расчётный счёт хранится в `company_banks` (уникален для компании)
- Менеджер выбирает конкретный счёт при создании заявки

#### applications — Заявки
```sql
CREATE TABLE applications (
    id SERIAL PRIMARY KEY,
    external_id VARCHAR(50) UNIQUE NOT NULL,  -- APP-{UUID}
    amount NUMERIC(15,2) NOT NULL,
    payer_inn VARCHAR(12) NOT NULL,
    payer_name VARCHAR(500),
    purpose TEXT NOT NULL,

    -- Связи
    company_id INTEGER REFERENCES companies(id),
    bank_id INTEGER REFERENCES banks(id),
    manager_id INTEGER REFERENCES users(id),
    company_bank_id INTEGER REFERENCES company_banks(id),

    -- Статусы
    status VARCHAR(50) NOT NULL,
    primary_check_status VARCHAR(50),
    primary_check_result JSON,

    -- Контакты клиента
    client_chat_id BIGINT,
    client_message_id INTEGER,

    -- Даты
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    sent_to_bank_at TIMESTAMP,
    approved_at TIMESTAMP,
    invoice_sent_at TIMESTAMP,
    client_confirmed_at TIMESTAMP,
    payment_received_at TIMESTAMP,
    scheduled_payout_date DATE,
    completed_at TIMESTAMP
);
```

#### approvals — Согласования
```sql
CREATE TABLE approvals (
    id SERIAL PRIMARY KEY,
    application_id INTEGER REFERENCES applications(id) ON DELETE CASCADE,
    role VARCHAR(50) NOT NULL,
    sequence INTEGER NOT NULL,
    required BOOLEAN DEFAULT TRUE,
    user_id INTEGER REFERENCES users(id),
    decision VARCHAR(20),  -- approved/rejected/null
    comment TEXT,
    decided_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### documents — Документы
```sql
CREATE TABLE documents (
    id SERIAL PRIMARY KEY,
    application_id INTEGER REFERENCES applications(id) ON DELETE CASCADE,
    type VARCHAR(50) NOT NULL,  -- invoice/contract
    number VARCHAR(100),
    file_path VARCHAR(500),
    file_url VARCHAR(500),
    generated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    sent_to_client_at TIMESTAMP
);
```

#### logs — Журнал действий
```sql
CREATE TABLE logs (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id),
    application_id INTEGER REFERENCES applications(id),
    action VARCHAR(100) NOT NULL,
    details JSON,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 📥 Установка и настройка

### Требования

- Docker 20.10+
- Docker Compose 2.0+
- 2 GB свободной оперативной памяти
- 5 GB свободного места на диске

### Шаг 1: Клонирование репозитория

```bash
git clone https://github.com/your-repo/payment_bot.git
cd payment_bot
```

### Шаг 2: Создание .env файла

```bash
cp .env.example .env
nano .env
```

### Шаг 3: Конфигурация .env

```env
# Telegram Bot Token (получить у @BotFather)
BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrsTUVwxyz

# PostgreSQL
POSTGRES_PASSWORD=your_secure_password_123

# Telegram ID администраторов (через пробел)
ADMIN_IDS=123456789 987654321

# API Ключи
ZCB_API_KEY=your_zcb_api_key_here
```

### Шаг 4: Запуск

```bash
# Запуск всех сервисов
docker compose up --build -d

# Проверка логов
docker compose logs -f bot

# Остановка
docker compose down

# Полная очистка (включая БД)
docker compose down -v
```

### Шаг 5: Проверка работоспособности

1. Откройте Telegram и найдите своего бота
2. Отправьте `/start`
3. Если вы в списке ADMIN_IDS, используйте `/admin`
4. Добавьте первого пользователя, компанию и банк

## ⚙️ Конфигурация

### Переменные окружения

| Переменная | Обязательная | Описание | Пример |
|------------|-------------|----------|--------|
| `BOT_TOKEN` | ✅ Да | Токен Telegram бота | `123:ABC...` |
| `POSTGRES_PASSWORD` | ✅ Да | Пароль PostgreSQL | `secure_pass_123` |
| `ADMIN_IDS` | ✅ Да | Telegram ID админов (через пробел) | `123 456 789` |
| `ZCB_API_KEY` | ⚠️ Рекомендуется | API ключ ЗЧБ | `zcb_key_...` |
| `DATABASE_URL` | ❌ Нет | URL БД (автогенерится) | `postgresql+asyncpg://...` |

### Получение BOT_TOKEN

1. Открыть [@BotFather](https://t.me/BotFather) в Telegram
2. Отправить `/newbot`
3. Следовать инструкциям
4. Скопировать полученный токен

### Получение Telegram ID

1. Открыть [@userinfobot](https://t.me/userinfobot)
2. Отправить `/start`
3. Скопировать `Id` из ответа

### Получение ZCB API Key

1. Зарегистрироваться на [Честный Бизнес](https://zachestnyibiznes.ru/)
2. Перейти в раздел API
3. Создать новый ключ
4. Скопировать ключ в `.env`

## 🔐 Безопасность

### Авторизация и аутентификация

- **Telegram ID** — уникальный идентификатор пользователя
- **Role-Based Access Control (RBAC)** — доступ строго по ролям
- **Middleware проверка** — на каждом запросе проверяется роль
- **Активация учётки** — деактивированные пользователи не имеют доступа

### Аудит действий

Все действия логируются в таблице `logs`:
```sql
INSERT INTO logs (user_id, application_id, action, details) VALUES
(123, 456, 'application_approved', '{"comment": "OK"}');
```

**Что логируется:**
- Создание/изменение пользователей
- Создание/изменение компаний и банков
- Все действия с заявками
- Изменение лимитов
- Генерация документов

### Защита данных

- ✅ PostgreSQL с правами доступа
- ✅ Пароли БД через переменные окружения
- ✅ Docker-изоляция
- ✅ Внешние ключи с CASCADE для целостности
- ✅ Индексы для быстрого поиска
- ✅ Логирование всех критических операций

### Рекомендации

1. **Используйте сильные пароли** для PostgreSQL
2. **Ограничьте ADMIN_IDS** только доверенными лицами
3. **Регулярно делайте бэкапы БД:**
   ```bash
   docker exec payment_bot_db pg_dump -U bot_user payment_bot > backup_$(date +%Y%m%d).sql
   ```
4. **Мониторьте логи:**
   ```bash
   docker compose logs -f bot
   ```
