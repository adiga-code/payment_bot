# Техническое задание
## Telegram-бот для автоматизации обработки платёжных заявок

**Версия:** 1.0
**Дата:** Январь 2026

---

## 1. Общие сведения

### 1.1 Наименование системы
Telegram-бот для автоматизации процесса обработки платёжных заявок с многоуровневой системой согласования (multi-signature workflow).

### 1.2 Назначение системы
Система предназначена для автоматизации полного цикла обработки платёжных заявок: от создания клиентом до финального одобрения руководителем, с промежуточными этапами проверки менеджером и оценки рисков банком.

### 1.3 Цели создания
- Автоматизация процесса согласования платежей
- Снижение времени обработки заявок
- Обеспечение прозрачности и контроля на каждом этапе
- Ведение полного аудита всех действий
- Контроль лимитов компаний и банков
- Минимизация рисков при проведении платежей

## 2. Функциональные требования

### 2.1 Роли пользователей

| Роль | Описание | Основные функции |
|------|----------|------------------|
| **Клиент (client)** | Инициатор платежа | Создание заявок на оплату |
| **Менеджер (manager)** | Первичная обработка | Проверка, одобрение/отклонение, выбор компании и банка |
| **Сотрудник банка (bank)** | Оценка рисков | Оценка рисков заявки, передача на финальное согласование |
| **Руководитель (supervisor)** | Финальное решение | Окончательное одобрение, работа с эскалациями |
| **Администратор (admin)** | Управление системой | Управление пользователями, компаниями, банками, статистика |

### 2.2 Функционал по ролям

#### 2.2.1 Клиент
- Регистрация в системе (автоматическая при первом обращении)
- Создание заявки на оплату:
  - Ввод суммы платежа
  - Ввод ИНН плательщика
  - Ввод назначения платежа
- Получение уникального номера заявки
- Получение уведомлений о статусе заявки
- Получение сформированных документов (счёт, договор)

#### 2.2.2 Менеджер
- Просмотр списка новых заявок (не назначенных)
- Просмотр своих заявок в работе
- Детальный просмотр заявки с информацией:
  - Сумма, ИНН, назначение платежа
  - Результаты первичной проверки
  - История согласований
- Одобрение заявки с выбором:
  - Компании-плательщика
  - Банка для проведения
- Отклонение заявки с указанием причины
- Просмотр статистики (сегодня/неделя/месяц)
- Пагинация списков (по 5 заявок на странице)

#### 2.2.3 Сотрудник банка
- Просмотр входящих заявок, направленных в банк
- Оценка рисков заявки:
  - Без риска — передача на финальное согласование
  - Минимальный риск — передача с пометкой
  - Высокий риск — эскалация или отклонение
- Просмотр статистики по банку
- Учёт дневных/недельных лимитов банка

#### 2.2.4 Руководитель
- Просмотр заявок, требующих решения
- Просмотр эскалированных заявок (отдельный раздел)
- Просмотр всех заявок
- Финальное одобрение:
  - Обновление использованных лимитов компании и банка
  - Генерация счёта на оплату
  - Генерация договора
  - Отправка документов клиенту
- Отклонение с указанием причины
- Возврат заявки менеджеру на доработку
- Просмотр статистики

#### 2.2.5 Администратор
- **Управление пользователями:**
  - Просмотр списка по ролям (все/менеджеры/руководители/клиенты)
  - Добавление пользователя (через пересланное сообщение или Telegram ID)
  - Назначение/изменение роли
  - Активация/деактивация пользователя
  - Удаление пользователя
  - Пагинация (по 8 на странице)

- **Управление компаниями:**
  - Просмотр списка компаний
  - Добавление компании (название, ИНН, лимиты)
  - Редактирование названия, ИНН
  - Управление лимитами (дневной/недельный/месячный)
  - Сброс использованных лимитов
  - Активация/деактивация компании
  - Удаление компании

- **Управление банками:**
  - Просмотр списка банков
  - Добавление банка (Chat ID группы, название, лимиты)
  - Редактирование названия, приоритета
  - Управление лимитами (дневной/недельный)
  - Сброс использованных лимитов
  - Приостановка/возобновление приёма заявок
  - Активация/деактивация банка
  - Удаление банка

- **Статистика системы:**
  - Количество пользователей по ролям
  - Количество активных компаний
  - Количество банков, принимающих заявки
  - Заявки за сегодня (количество и сумма)

### 2.4 Система лимитов

#### Компании:
- Дневной лимит (daily_limit)
- Недельный лимит (weekly_limit)
- Месячный лимит (monthly_limit)
- Текущее использование по каждому периоду

#### Банки:
- Дневной лимит (daily_limit)
- Недельный лимит (weekly_limit)
- Текущее использование
- Приоритет (для сортировки)
- Флаг доступности (is_available)

### 2.5 Многоэтапное согласование (Multi-Signature)

Каждая заявка проходит через цепочку согласований:

| Этап | Роль | Sequence | Действия |
|------|------|----------|----------|
| 1 | manager | 1 | Проверка, выбор компании/банка |
| 2 | bank | 2 | Оценка рисков |
| 3 | supervisor | 3 | Финальное решение |

Каждое согласование фиксируется:
- Кто согласовал (user_id)
- Решение (approved/rejected)
- Комментарий
- Время принятия решения

### 3.3 Паттерны проектирования

- **Repository Pattern** — абстракция доступа к данным
- **Service Layer** — бизнес-логика отделена от обработчиков
- **Middleware Chain** — цепочка обработки запросов
- **FSM (Finite State Machine)** — многошаговые формы
- **Dependency Injection** — внедрение зависимостей
- **Generic Repository** — базовый CRUD для всех сущностей

### 5.2 Inline-клавиатуры

Все меню и действия реализованы через Inline Keyboard Markup с callback_data для асинхронного взаимодействия.

#### Пример: Главное меню менеджера
```
┌────────────────────────────────┐
│ 📥 Новые заявки (5)            │
├────────────────────────────────┤
│ 📋 Мои заявки (12)             │
├────────────────────────────────┤
│ 📊 Статистика                  │
└────────────────────────────────┘
```

#### Пример: Детали заявки для руководителя
```
┌────────────────────────────────┐
│ ✅ Одобрить                    │
├────────────────────────────────┤
│ ❌ Отклонить                   │
├────────────────────────────────┤
│ ↩️ Вернуть менеджеру          │
├────────────────────────────────┤
│ ◀️ Назад                       │
└────────────────────────────────┘
```

### 5.3 FSM-диалоги

Многошаговые формы реализованы через Finite State Machine:

**Создание заявки (клиент):**
1. `waiting_for_amount` — ввод суммы
2. `waiting_for_inn` — ввод ИНН
3. `waiting_for_purpose` — ввод назначения

**Добавление компании (админ):**
1. `waiting_company_name` — название
2. `waiting_company_inn` — ИНН
3. `waiting_company_daily_limit` — лимит
